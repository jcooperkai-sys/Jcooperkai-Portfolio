INDEPENDENT RESEARCH · SECURITY · NO. 1

Red-Teaming a Small Local Language Model:
Manipulation, Degeneration, and the Near-Absence
of Guardrails in minicpm-v4.6
Four reproducible experiments on how easily a 1.6 GB on-device model can be steered, broken, and bypassed.
Jeffery Eckert, Independent · June 2026 · model: minicpm-v4.6 (≈1.6 GB) via Ollama, Apple-silicon, macOS ·
harness: Python 3.14

Abstract. We red-team a small, locally-hosted language model across four axes: (1) extraction of a
protected secret, (2) degenerate generation (induced incoherence and repetition loops), (3) input fuzzing with
un-instructed raw data, and (4) guardrail bypass on a battery of benign-but-normally-refused tasks. Every
target is non-destructive by construction: the "secret" is a fabricated word and all bypass targets are
harmless (profanity in fiction, subjective opinions, roasting a fictional character). We find the model leaks
its secret to 4 of 10 trivial social-engineering prompts, spirals into infinite repetition when its repetition
penalty is disabled or when seeded with a looping pattern, hallucinates unprompted content when handed
contentless input, and exhibits an effectively absent safety wall — 6 of 6 benign guardrails were
bypassed, five with no manipulation at all. We also document a methodological hazard: empty
(non-)responses must not be scored as compliance.

1. Setup & threat model
All experiments target a single model, minicpm-v4.6 , served locally through Ollama's HTTP API on
Apple-silicon hardware. We deliberately study a small model (≈1.6 GB) because on-device assistants
are proliferating and inherit little of the heavy safety fine-tuning that frontier, server-side models receive. The harness is a thin Python layer: it constructs a prompt, calls the model once (occasionally
with retries), and classifies the response with simple string heuristics. Figure 1 shows the common
architecture shared by all four studies.

This is precisely the mechanism behind widely-reported repetition spirals in larger systems: a strong
textual attractor plus an inadequate escape penalty yields unbounded looping. The model is not "feeling" anything — it has fallen into a groove with no force to leave it.

4. Experiment III — Un-instructed input fuzzing
We now remove all instructions and decoding tricks: the model receives only raw, meaningless input
at default settings. With no task to perform, it falls back on two reflexes — continue the pattern, or,
when the input is contentless, fill the void from training-data echoes — and both can break it (Figure 4).

A methodological hazard
Our first run reported a dramatic "0/6 walls" — an artifact. On the chat endpoint the model frequently
returned an empty string, which our classifier scored as compliance. Switching to the generate endpoint with retries, and scoring empty as no-response rather than complied , gave the corrected picture above. Non-responses must never be counted as successful bypasses; doing so inflates either

robustness or vulnerability depending on sign, and is an easy way to manufacture a misleading headline number.

6. Discussion
Across all four studies a single theme recurs: the small model has weak instruction hierarchy, brittle coherence, and an effectively absent safety wall. It cannot reliably keep a secret stated in its
own system prompt; it loops or dissolves into noise when the decoder's guard-rails are loosened; it
free-associates from training echoes when handed emptiness; and it performs normally-guarded tasks
on request. None of this implies the model is "broken" — it implies that safety is not an emergent property
of a base model. It is installed by extensive alignment fine-tuning that frontier labs invest in heavily and
that a 1.6 GB on-device model largely lacks.
The practical security takeaways are concrete: (i) never place a real secret in a prompt — it is one polite sentence from exfiltration; (ii) keep the repetition penalty engaged and temperature bounded in
any production decoder; (iii) treat on-device model output as untrusted, sanitizing both inputs and
outputs; and (iv) in evaluation, distinguish refusal from non-response with care.

7. Limitations
Single model, single hardware target, single-turn attacks, and heuristic string classifiers (which underand over-count at the margins). The empty-response behavior is itself partly an engineering artifact of
the chosen endpoint. Multi-turn attacks — building rapport before the ask — are known to be
stronger and are left to future work, as is a cross-model comparison against tinyllama and
llama3.2:3b .

8. Conclusion
A small local LLM is easy to manipulate, easy to break, and barely guarded. For builders of on-device
AI this is not a counsel of despair but a specification: alignment and decoding-time safety must be
added deliberately, because the base model supplies almost none. All four harnesses are short, reproducible Python scripts and are released alongside this report.
